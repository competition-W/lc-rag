# 当前检索流程分析

## 1. 检索流程概览

从用户输入查询到模型生成最终回答的完整流程如下：

```
用户输入 → 统一检索入口 → 索引获取 → 策略路由 → 执行检索 → 结果处理 → LLM生成 → 返回结果
```

## 2. 详细流程说明

### 2.1 统一检索入口 (`unified_query_service`)

**位置**：行45-129

**核心功能**：
- 确保Embedding模型初始化
- 获取对应部门的索引
- 根据查询意图和过滤条件选择合适的检索策略
- 处理检索结果，调用LLM生成最终回答

**关键步骤**：
1. 初始化Embedding模型
2. 获取部门索引
3. 记录调试日志，展示接收到的请求参数
4. 根据意图和过滤条件路由到不同检索策略
5. 检查检索结果数量
6. 调用LLM生成回答
7. 返回最终结果

### 2.2 检索策略路由

**位置**：行69-106

**路由逻辑**：

| 意图类型 | 是否有过滤条件 | 选择的检索策略 |
|---------|--------------|--------------|
| sample_query/project_query | 是 | 结构化表格检索 |
| sample_query/project_query | 否 | 结构化表格检索（使用查询文本作为关键词） |
| 其他意图 | 是 | 结构化表格检索 |
| 其他意图 | 否 | 通用语义检索 |

### 2.3 结构化表格检索 (`_strategy_structured_table`)

**位置**：行395-591

**核心功能**：处理结构化表格数据的检索，支持多轮降级策略

**关键步骤**：
1. **构建过滤条件**：
   - 强制添加部门隔离过滤
   - 添加用户提供的过滤条件
   - 跳过包含特殊字符的字段

2. **执行LlamaIndex检索**：
   - 创建检索器，设置相似度top_k=1000
   - 执行检索，获取所有匹配节点
   - 记录命中数量

3. **第一轮降级策略**：如果检索结果为空
   - 简化过滤条件，移除可能有问题的字段
   - 重新执行检索

4. **第二轮降级策略**：如果仍然失败
   - 直接使用PyMilvus API
   - 构建PyMilvus查询表达式
   - 执行查询，获取结果
   - 将结果转换为LlamaIndex Node格式

5. **第三轮降级策略**：如果还是失败
   - 使用更简单的LlamaIndex检索器
   - 只添加不包含特殊字符的过滤条件
   - 尝试使用多个搜索词

6. **结果处理**：
   - 挑选前N条数据作为best_rows（用于LLM）
   - 格式化所有结果，返回给调用方

### 2.4 通用语义检索 (`_strategy_general_semantic`)

**位置**：行596-614

**核心功能**：处理通用语义检索，支持重排序

**关键步骤**：
1. 构建仅包含部门过滤的条件
2. 执行语义检索，获取候选节点（扩大检索范围，top_k*4）
3. 对候选节点进行重排序
4. 返回最终结果

### 2.5 LLM生成模块 (`_generate_summary`)

**位置**：行291-348

**核心功能**：根据检索结果生成最终回答

**关键步骤**：
1. **精细化构建上下文**：
   - 使用`_format_node_for_llm`函数格式化每个节点
   - 根据查询意图提取相关指标数据
   - 结构化输出，方便LLM理解

2. **获取系统提示词**：
   - 根据意图从prompt_manager获取系统提示词
   - 构建用户提示词，包含查询和上下文

3. **调用LLM生成回答**：
   - 检查LLM是否初始化
   - 调用LLM生成回答
   - 记录生成结果和错误信息

### 2.6 辅助函数

#### 2.6.1 重排序 (`_perform_rerank`)
**位置**：行619-651
**功能**：安全处理重排序，支持空列表、空查询、插件缺失等情况

#### 2.6.2 节点格式化 (`_format_nodes`)
**位置**：行653-676
**功能**：将检索节点转换为统一格式，支持是否保留full_row_json

#### 2.6.3 节点格式化（LLM专用）(`_format_node_for_llm`)
**位置**：行169-285
**功能**：根据查询意图提取相关指标数据，格式化节点为LLM易读的字符串

## 3. 关键设计特点

### 3.1 多级降级策略
- 采用LlamaIndex检索 → 简化过滤条件 → PyMilvus API → 简单LlamaIndex检索的多级降级策略
- 确保在各种情况下都能尽可能返回结果

### 3.2 精细化上下文构建
- 根据查询意图提取相关指标数据
- 结构化输出，方便LLM理解
- 排除无关字段，减少上下文长度

### 3.3 意图驱动的检索
- 根据查询意图选择不同的检索策略
- 根据查询意图提取不同类型的指标数据
- 根据查询意图获取不同的系统提示词

### 3.4 安全的重排序
- 处理各种异常情况
- 降级机制，确保即使重排序失败也能返回结果

## 4. 检索流程示例

以用户查询"帮我查询小鼠心脏的实验指标"为例：

1. 用户输入查询
2. 统一检索入口接收请求，意图识别为"sample_query"
3. 路由到结构化表格检索策略
4. 构建过滤条件：
   - 部门隔离：department == 当前部门
   - 解析查询关键词：小鼠、心脏、实验指标
   - 构建字段过滤条件
5. 执行LlamaIndex检索
6. 检查检索结果
7. 调用LLM生成回答：
   - 精细化构建上下文，提取实验指标相关数据
   - 获取对应意图的系统提示词
   - 调用LLM生成回答
8. 返回最终结果

## 5. 代码优化建议

1. **简化检索流程**：当前检索流程过于复杂，包含多级降级策略，可以考虑简化
2. **优化日志记录**：增加更详细的日志记录，便于调试和监控
3. **统一过滤条件处理**：当前代码中过滤条件处理较为分散，可以考虑统一处理
4. **优化LLM上下文构建**：进一步优化上下文构建，减少上下文长度，提高生成质量
5. **增加缓存机制**：对于频繁查询的结果，可以考虑增加缓存机制，提高检索效率

## 6. 总结

当前的检索流程设计较为完善，包含多级降级策略、精细化上下文构建、意图驱动的检索等特点。通过统一的检索入口，根据查询意图和过滤条件选择合适的检索策略，确保在各种情况下都能尽可能返回结果。同时，通过精细化的上下文构建和意图驱动的提示词，提高了LLM生成回答的质量。
